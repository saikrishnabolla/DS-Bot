# Cue 的愿景

## Cue 是什么

Cue 是一个由持久 Bot 组成的个人助手。每个 Bot 都有稳定的职责、记忆、工作文件夹和对话记录。Bot 可以单独工作，也可以组队、互相交接。

## 产品形态

Cue 自己管理 Pi Durable host 和界面。桌面应用是主要产品。Docker 运行同一个 host，但不提供电脑操控和本地浏览器控制等桌面功能。

## 核心要求

1. Bot 在重启后保留身份和历史。
2. 普通工作只用一个 Bot 就能完成，不让用户管理上下文。
3. 团队工作有明确负责人，进度可见。
4. Main Bot 权限与普通 Bot 分开。
5. 记忆、文件夹、权限和密钥都有明确范围。
6. 用户可以检查和中断工作。
7. 更换模型 provider 或本地 Agent 不改变团队模型。
8. 对外操作必须有对应权限或审批。
9. 数据由用户控制。
10. 自有 host 可以脱离桌面应用测试。

## 取舍原则

- 优先做好一条可靠流程，不堆多条半成品流程。
- 明确分开 host、桌面应用和 provider 边界。
- 迁移时保住用户数据和已有行为。
- Cue 不再支持某个 host 或格式时，删掉兼容代码。

## 谁来定方向

维护者决定产品方向。设计改动在实现前写入 `docs/plans/`。
